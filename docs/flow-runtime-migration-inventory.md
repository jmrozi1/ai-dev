# Issue 23 Runtime Capability Disposition Inventory

Current source authority: current `scratch`/`main` HEAD at the start of Issue 23 checkpoint 1.

This inventory records the runtime surface that exists today, plus required planned-but-not-present coverage items that Issue 23 must account for explicitly. It is a migration map only. It does not remove or rename commands.

## Checkpoint 8 Status

- Implemented: top-level `get`, `set`, and `unset` commands are removed from runtime dispatch and help.
- Implemented: repository-scoped runtime output routing via `.ai-dev/config.json` is retired; `ai_dev_flow/config.py` is deleted.
- Implemented: local exclude synchronization retains only deterministic Flow state coverage (`.ai-dev/`) and no longer tracks configured output files.
- Compatibility note: existing `.ai-dev/config.json` files are ignored by retained commands and left in place unless manually removed.

## Checkpoint 9 Status

- Implemented: runtime dispatch through legacy `ai-dev` / `ai-dev flow` namespaces is retired.
- Implemented: runtime command surface now consists of fixed direct executables via prefixed launchers: lifecycle commands (`start`, `patch`, `status`, `diff`, `commit`, `reset`, `promote`, `complete`, `block`, `resume`) plus ticket commands (`ticket-create`, `ticket-show`, `ticket-query`).
- Implemented: runtime `config`, `apply`, and `update` commands are removed.
- Implemented: bootstrap remains responsible for prefixed launcher installation, collision handling, and ownership-safe reconciliation.

## Issue 23 Assumption Checks And Recommended Boundaries

| Assumption or question | Current-source finding | Recommended boundary for Issue 23 |
| --- | --- | --- |
| `flow-diff` can reuse current review diff construction without retaining generated review machinery. | The retained implementation keeps only `_flow_diff_cached_changes`, `_flow_diff_workflow_changes`, untracked diff helpers, and `compare_main_and_scratch`; the package/task/verification machinery was deleted in checkpoint 4. | Keep `flow-diff` read-only and independent from review packaging. |
| Staged, unstaged, untracked, and committed checkpoint changes are easy to map forward. | Historically, `handle_review()` called `sync_local_excludes()` and `stage_all_changes()` before collecting diffs. Checkpoint review then used cached/index diff only. Workflow review (`--all`) combined committed `main...scratch` diff with cached overlay diff. Untracked and unstaged changes were implicitly folded into the index by auto-staging. | Keep the historical note explicit; retained `flow-diff` should stay read-only and must not silently preserve those auto-staging semantics. |
| `--all` should map directly to branch comparison only. | Historically, `review --all` was not just branch comparison. It combined `git diff main...scratch` with cached overlay changes. | The retained `flow-diff --all` semantics should remain explicit about including workflow commits plus current changes. |
| Current configuration precedence can be simplified without losing useful behavior. | Retained runtime state is deterministic repository-local Flow state (`.ai-dev/workflow.json`, `.ai-dev/blocked-workflows.json`, `.git/info/exclude` managed block). User YAML runtime configuration/editing is retired. | Keep retained deterministic state explicit and document that stale configuration files are preserved but ignored. |
| Stale-launcher cleanup does not need installation ownership metadata. | Safe cleanup now depends on bootstrap-owned prefixed launcher tracking (`prefixed-launcher-ownership.json`) and digest checks. Divergent files fail closed. | Preserve ownership-based cleanup and fail-closed behavior for prefixed launchers. |
| Cross-platform launcher behavior still needs fresh design work. | Current runtime already supports POSIX and Windows prefixed launchers (`flow-*` or custom prefix) and direct internal routing through `__ai_dev_flow_exec__`. | Reuse existing cross-platform launcher rendering and ownership logic instead of replacing it wholesale. |
| Proposed VS Code stdin delivery can create a usable untitled diff buffer. | Current runtime has editor path launching and clipboard/stdout delivery only.
